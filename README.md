# UC San Diego Student Founder Funding Opportunities

Static GitHub Pages site listing curated grants, pitch competitions, accelerators and fellowships for
UC San Diego student founders. Design follows ucsd.edu branding (navy / gold, condensed uppercase headings)
and the card/tab layout of studentfounderhq.com.

Live: https://eirik-wg.github.io/ucsd-opportunities/

## How the data flows

```
Reviewed workbook (Reviewed_2026) ──export_site_data.ps1──► data/airtable_import.csv ──import once──► Airtable (source of truth)
                                                                                                          │
                                                    GitHub Action (daily) ◄── scripts/sync-airtable.mjs ◄─┘
                                                            │
                                                            └──► data/opportunities.json ──► website + newsletter
```

- `data/opportunities.json` is generated by `export_site_data.ps1` (PowerShell + Excel COM) from
  `20260929_Funding opportunities_reviewed.xlsx`. It keeps only active Tier 1–2 opportunities (max 80),
  sorted by tier then deadline.
- The site computes status client-side from `deadline` + `deadlineKind`:
  - `rolling` → **Open · rolling**
  - `confirmed` and date in the future → **Open** / **Closes in N days**
  - `expected` (projected from last cycle) and date in the future → **Upcoming / expected**
  - date in the past → **Closed** (shown in "Recently closed" for 120 days)

### Refreshing the data

```powershell
powershell.exe -ExecutionPolicy Bypass -File "export_site_data.ps1"
git add data/opportunities.json
git commit -m "Refresh opportunities data"
git push
```

## Airtable as source of truth

### 1. Create the base

1. In Airtable, create a base and import `data/airtable_import.csv` (548 rows, one per opportunity) as a table named **Opportunities**.
2. Set field types after import:
   - `Estimated Deadline Date` → Date (ISO)
   - `UCSD Run`, `Show on Website` → Checkbox
   - `Type`, `Funding Model`, `Deadline Kind`, `Founder Stage`, `Student Startup Fit`, `Priority Tier`, `Geography`, `Industry`, `Status` → Single select
   - `Eligibility` → Long text (one requirement per line)
3. Create a view named **Website** filtered on `Show on Website` is checked (optionally also `Status` ≠ Inactive), sorted by `Priority Tier` then `Estimated Deadline Date`.

### 2. Connect the sync

1. Create a personal access token at https://airtable.com/create/tokens with scope `data.records:read` and access to the base.
2. In the GitHub repo: Settings → Secrets and variables → Actions → add secrets **`AIRTABLE_TOKEN`** and **`AIRTABLE_BASE_ID`** (`app…`). Optional variables `AIRTABLE_TABLE`, `AIRTABLE_VIEW` override the defaults `Opportunities` / `Website`.
3. Run **Actions → Sync opportunities from Airtable → Run workflow** once. It runs `scripts/sync-airtable.mjs`, commits `data/opportunities.json` if it changed, and redeploys Pages. It then repeats daily (06:15 UTC).

From then on, editing a record in Airtable updates the website on the next sync; the newsletter can read the same **Website** view.

### Field names expected by the sync

`Program Title`, `Organizer`, `Program Description`, `Type`, `Funding Model`, `Funding Amount/Prize Amount`,
`Estimated Deadline Date`, `Deadline Kind` (confirmed | expected | rolling), `Next Deadline`, `Recurring`,
`Eligibility Label`, `Geography`, `Industry`, `Founder Stage`, `Best For`, `Student Startup Fit`, `Priority Tier`,
`UCSD Run`, `Eligibility`, `Website link`, `Status`, `Show on Website`.

`app.js` can also read Airtable directly in the browser (`CONFIG.airtable`) for local testing, but do **not** commit a token there — the scheduled sync is the production path.
